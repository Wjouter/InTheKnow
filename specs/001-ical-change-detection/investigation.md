# Investigation: MyTimetables (Inholland) iCal feeds

**Date**: 2026-09-24
**Input**: the four example links (plus one English-language link, same timetable) in `mytimetable example links.md` (2 groups × 2 links each),
fetched live from `mytimetables.inholland.nl`. Link tokens are deliberately not reproduced here.

## 1. Link anatomy

```
https://mytimetables.inholland.nl/ical?<HEX>&timetable=<T>&eu=<E>&h=<H>
```

| Part | Example (decoded) | Meaning |
|------|-------------------|---------|
| `<HEX>` (bare, valueless first param) | `6ab568c1` → 2026-09-24 18:15:29 UTC | Unix timestamp (hex) of when the link was generated. **Optional**: the feed is returned byte-identical without it. |
| `timetable` | base64 → `Xedule!xedule_studentgroup!IFGFISJSGZLFINCFKMYQ`; last segment is base32 → `ALTI26VT4ES1` | Which timetable: source system (`Xedule`), timetable kind (`xedule_studentgroup`), and the id (here the student-group code). |
| `eu` | base64 → `<numeric user id>` | Most likely the id of the user who generated the link. Same for both groups in the examples (same user). |
| `h` | 32-byte base64url | Signature/token over the other params. Identical for the two links of the same timetable, so it does **not** cover `<HEX>`. |

## 2. Duplicate-link findings

- Links for the same timetable generated by the same user differ **only** in `<HEX>`; `timetable`, `eu`
  and `h` are identical, and the feeds are byte-identical when fetched in the same second.
- Therefore: **same-user duplicates = equal after dropping `<HEX>`**. Verified.
- Classmates' links for the same group will (by inference) share `timetable` but differ in `eu` and `h`.
  Not verified — needs a second user's link for the same group. The content of a student-group timetable
  should not depend on who requested it, but a personal/custom timetable kind might. Cross-user merging
  should therefore only apply to `xedule_studentgroup` timetables until verified otherwise.
- Event `UID`s (`Xedule!<base32 numeric id>@schedule.inholland.nl`) are stable and **global**: 51 events
  (holidays, shared courses) appear with the same UID in both groups' feeds.
- The calendar name `X-WR-CALNAME` is `Hogeschool Inholland - Rooster - <group code>`, which can be used to
  confirm that a fetched feed matches the decoded `timetable` id.

## 3. Invalid links fail silently

A link with a wrong `h` returns **HTTP 200 with a valid, empty calendar** (749 bytes, correct
`X-WR-CALNAME`, zero events). An invalid or revoked link is therefore indistinguishable from "all events
cancelled" unless the system treats "had events, now has none" as a failed check. A link must also be
validated (non-empty feed) before it is merged into an existing calendar, otherwise a forged `timetable`
value with a junk `h` would "match".

## 4. Feed content (per VEVENT)

| iCal property | Example | Usable for change detection? |
|---------------|---------|-----|
| `UID` | `Xedule!GI3TINRXGY3A@schedule.inholland.nl` | Identity key (stable). |
| `SUMMARY` | `ROS2 basics`, `[CONCEPT] Pasen` | Yes – event name. `[CONCEPT] ` prefix marks a tentative event. |
| `DTSTART` / `DTEND` | `;TZID=Europe/Brussels:20260901T083000`; some (holidays) are floating local times without TZID | Yes – event time. |
| `LOCATION` | `AL00.A1.38`, `AL00.A1.20\, AL00.A1.21`, or empty | Yes – room(s), comma-separated. Holiday (`Vakantie`) events carry huge lists truncated with `...` → unreliable for those. |
| `DESCRIPTION` → `Type:` | `Les`, `Toets`, `Vakantie`, `Afspraak` | Extract; activity type. |
| `DESCRIPTION` → `Ruimte(s):` | duplicate of LOCATION | — |
| `DESCRIPTION` → `Docent(en):` | `Last1\, First1\, Last2\, First2` | Yes – teachers, as *Last, First* pairs (comma-joined, so split in pairs). Absent on holidays. |
| `DESCRIPTION` → `Groep(en):` | `ALTI26VT4ES1` (or hundreds for holidays) | Extract; groups attending. |
| `DESCRIPTION` → `Laatst gesynchroniseerd op …` | `2026-09-24 om 20:24 CEST` | **No** – changes every minute. |
| `STATUS` | always `CONFIRMED` (386/386) | No signal seen; cancellations presumably appear as removal from the feed. |
| `SEQUENCE` | always `0` | No. |
| `DTSTAMP`, `CREATED`, `LAST-MODIFIED` | = time of fetch | **No** – change on every fetch. |

The feed spans the whole academic year including past events (starts 2026-09-01).

## 5. Server behaviour

- Response: `text/calendar`, ~230–260 KB per group feed.
- No `ETag`; `Last-Modified` = time of request → conditional requests are useless; every check is a full download.
- `Expires` = request time + 1 hour, suggesting the server considers hourly refresh adequate.

## 6. Language

The feed language is an **account-wide** setting of the link owner: after switching the account to English,
the *same* link (same `timetable`/`eu`/`h`) returned `content-language: en-GB`. Query parameters or
`Accept-Language` do not change it. Both groups were compared event-by-event in NL and EN: same UIDs, and
times, rooms, teachers and groups identical. Only these differ:

| Item | Dutch | English |
|------|-------|---------|
| Calendar name | `Hogeschool Inholland - Rooster - <group>` | `Inholland University of Applied Sciences - Timetable - <group>` |
| Draft prefix in `SUMMARY` | `[CONCEPT] ` | `[DRAFT] ` |
| Label: type | `Type:` | `Type:` |
| Label: rooms | `Ruimte(s):` | `Room(s):` |
| Label: teachers | `Docent(en):` | `Staff member(s):` |
| Label: groups | `Groep(en):` | `Student set(s):` |
| Type values | `Les`, `Toets`, `Vakantie`, `Afspraak` | `Lesson`, `Test`, `Holiday`, `Appointment` |
| Footer | `Deze afspraak wordt beheerd door MyTimetables.` | `This appointment is managed by MyTimetables.` |
| Sync line | `Laatst gesynchroniseerd op 2026-09-24 om 20:24 CEST` | `Last synchronised on 2026-09-24 at 20:47 CEST` |

Consequence: because the language belongs to whoever owns the link being fetched, a shared calendar can flip
language between checks. Everything in this table must be normalised so that a flip records no changes.

## 7. Conclusions for the spec

1. MyTimetables features are bound to an operator-configured list of domains (default: `mytimetables.inholland.nl`),
   each with per-feature toggles; Semestry runs on other institutions' domains too, and domains can change.
2. Calendar identity = host + decoded `timetable` value (+ `eu` for non-student-group kinds); `<HEX>` ignored.
   Generic links: identity = normalised URL.
3. Validate every newly added link with one fetch before accepting/merging it; keep all validated links per
   calendar so a revoked one can be replaced by another.
4. Change detection compares parsed fields per `UID` against the stored state; volatile fields (§4 "No") are ignored.
5. Draft prefix → tentative status; type values and labels mapped NL/EN to language-independent values.
6. A MyTimetables feed that drops to zero events after previously having events is a failed check, not mass cancellation.
